DBML Syntax Highlighting Test

To test DBML syntax highlighting:

  1. Start the dev server: pnpm tauri:dev
  2. Open a workspace and connect to a database
  3. Open the ERD Panel or any panel with CodeEditor
  4. Test with the following DBML code:
// DBML Test File
Project my_database {
  database_type: 'PostgreSQL'
  Note: '''
    Multi-line project note
    Testing DBML syntax highlighting
  '''
}

// Reusable table fields
TablePartial timestamps {
  created_at timestamp [default: `now()`]
  updated_at timestamp [default: `now()`]
}

Table users [headercolor: #3498DB] {
  ~timestamps
  id integer [pk, increment]
  email varchar(255) [unique, not null]
  name varchar [not null, note: 'User full name']
  status user_status [default: 'active']

  indexes {
    email [unique, name: 'idx_email']
    (email, created_at)
  }

  Note: 'User accounts table'
}

Table posts {
  id integer [pk]
  title varchar(255) [not null]
  body text [note: 'Post content']
  author_id integer [ref: > users.id]
  status post_status
  created_at timestamp [default: `now()`]
}

// Enums
enum user_status {
  'active'
  'inactive'
  'suspended'
}

enum post_status {
  'draft' [note: 'Work in progress']
  'published'
  'archived'
}

// Relationships
Ref: posts.author_id > users.id [delete: cascade, update: no action]

/* Block comment
   Testing multi-line
   comments */

TableGroup blog [color: #FCA311] {
  posts
  tags

  Note: 'Blog tables'
}

// Sticky note
Note important_info {
  '''
  Remember to index
  foreign key columns
  for better performance
  '''
}

Expected Highlighting:

  • Keywords (Project, Table, Enum, Ref, etc.) - Blue/Purple
  • Data Types (integer, varchar, text, timestamp) - Green/Teal
  • Constraints (pk, unique, not null) - Orange/Yellow
  • Strings ('...') - Red/Pink
  • Comments (// and /* */) - Gray
  • Numbers - Cyan
  • Identifiers (table/column names) - Default text
  • Operators (>, <, -) - Purple
